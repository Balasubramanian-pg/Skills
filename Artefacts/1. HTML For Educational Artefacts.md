# MASTER PROMPT — Icon-Driven Process Straw Model (HTML)

You are producing a single, self-contained HTML file: a **visual straw model** of a business process, styled as an internal consulting training slide.

The diagram must SHOW, not TELL. A reader should understand the process from the shapes and flow alone, before reading a single label. No company branding, no logos, no emoji, no wall-of-text, no generic clipart.

---

## 0. INPUTS — I will fill these before you start

- **PROCESS**: <name> — <one-sentence purpose>
- **NARRATIVE OBJECT**: <the single thing that transforms along the flow,
  e.g. "one claim" or "one order">
- **FLOW SHAPE**: <e.g. 3 steps forward → turn down → 3 steps back → converge>
- **STEPS**: ordered list. For each:
  - name
  - 2–4 short tags / standard codes
  - icon metaphor — what ACTION or TRANSFORMATION it depicts
  - theory — 2–3 sentences, plain language, no jargon dump
- **SINK**: <terminal element: name + 3–5 data sources>

If any input is missing, ask once, then proceed with sensible defaults.

---

## 1. OUTPUT

One `.html` file. Everything inline: CSS, SVG, JS. No build step, no external
JS libraries. Google Fonts allowed. Must render correctly opened directly
from disk.

---

## 2. DESIGN SYSTEM (do not deviate)

**Type**: Plus Jakarta Sans, weights 400/500/600/700/800, loaded from Google
Fonts. `font-feature-settings:"ss01","cv11"`. All headings, chips, labels and
numbers use **600 (semibold)**. Reserve 700 only for tiny monospace code tags
inside SVGs.

**Palette** — one accent per step, used consistently:
  ink #16324f · ink2 #5b6a7a · ink3 #93a1af · line #e2e8ee · paper #fff
  blue #2F6FB0 · teal #17858A · indigo #4B5FA5 · amber #B4762B
  plum #8A4D86 · green #3E8A5F · red #C0574F
Each card gets `--c` (accent) and `--t` (10%-tint of same).

**Canvas**: page bg #eef1f5, white slide, max-width ~1180px, generous padding
(34/38px), 2px radius, single soft shadow. Thin gradient rule under the title.

**Spacing**: everything on a 4px rhythm. Cards fixed height so the grid stays
aligned whether flipped or not.

---

## 3. LAYOUT

Grid, not flex-wrap. Connectors are grid cells, not absolutely positioned.

- Forward steps: left → right, top row.
- Vertical hand-off: dashed arrow down at the end of the row.
- Return steps: right → left, second row, **arrows reversed** (chevron points
  left, dashed line tinted green to signal "payment / return path").
- Vertical hand-off into the sink.
- Sink: full-width dark band (#1E3350), white text, circular icon, and a row
  of small source pills each with its own mini icon.

Forward connectors: neutral grey #a9b6c3, animated dashes.
Return connectors: green #7FBB98, animated dashes.

---

## 4. CARD SPEC

Fixed height ~188px. `perspective:1400px`. Two faces, `preserve-3d`,
`backface-visibility:hidden`.

**Front**
- Top-left ribbon: 3px accent bar.
- Top-right: step number, 10px, 600 weight, muted.
- Centered SVG icon, ~68px tall.
- Title: 13.5px, 600.
- Tag chips: 8.5px, 600, uppercase, accent color on tint background.
- Bottom-right: small circular-arrow glyph (flip affordance).

**Back**
- Same card, rotated 180°. Background: white → tint gradient.
- Kicker: `01 · TITLE` in 8.5px 700 uppercase accent.
- Theory paragraph: 10.5px, 500 weight, line-height 1.62, ink2.
- Opposite-direction circular-arrow glyph bottom-right.

**Hover/focus dimming**: hovering the grid dims all cards to 45% opacity;
the hovered/focused/flipped card stays at 100% and lifts 2px.

---

## 5. ICON QUALITY BAR — read this twice

This is where most attempts fail. A cheap icon is worse than no icon.

**Every icon must**:
- Be inline `<svg viewBox="0 0 200 72">`, stroke-based, 1.4–1.8px strokes,
  round caps and joins, geometric and grid-aligned.
- Depict an **action or transformation**, not a noun. A "coding department"
  is not a folder — it is *text becoming codes*. A "filter" is not a funnel —
  it is *input, mechanism, and branches to pass/reject*.
- Contain **at least 3 distinct visual elements** that tell a mini-story
  (e.g. document + arrow + code chips; or claim + gate + two outcome tokens).
- Use **the card's own accent** as primary, neutral ink for structure, and one
  semantic accent (green/red) only when showing good-vs-bad outcomes.
- Read clearly at 100% zoom. If it looks like a placeholder, redo it.

**Never**:
- Emoji, unicode glyphs, icon fonts, or SVG "clip art" bundles.
- A single rectangle labelled with a concept. That is a box, not an icon.
- A funnel, a plain magnifying glass, a generic "gear" — unless paired with
  what goes in and what comes out.
- Inconsistent stroke weights between cards. Use one weight system throughout.
- Floating stray marks or marks that don't participate in the metaphor.

**Self-audit before returning**: for each icon, silently answer —
"Would a designer call this intentional, or cheap?" If cheap, redraw.

---

## 6. INTERACTION

- Click / tap any card → 3D flip, ~0.62s `cubic-bezier(.4,.15,.2,1)`.
- Keyboard: `Enter` and `Space` toggle. Cards are `tabindex="0"`,
  `role="button"`, and toggle `aria-pressed`.
- `:focus-visible` shows a 2px accent outline.
- Add a one-line subtitle under the title:
  "Click any card to flip it and read the theory behind the step."
- Multiple cards may be flipped simultaneously.

---

## 7. MOTION

- Connector dashes animate via `stroke-dashoffset` (~1.2s linear infinite).
- Under `prefers-reduced-motion: reduce`: kill connector animation and
  collapse flip duration to ~0.01ms.

---

## 8. CONTENT RULES

- Chips: 2–4 per card, uppercase, standard industry codes or 1–2 word tags.
- Theory back: **2–3 sentences**. Plain language. Explain *why* this step
  exists and *what breaks* if it fails. No bullet lists, no headers, no
  marketing voice.
- Step numbers appear on both faces so sequence stays legible when several
  cards are flipped.
- Sink band: name + acronym, one-line purpose, then source pills.

---

## 9. WHAT TO AVOID

- Wall-of-text cards, paragraphs on the front face.
- Icons that are just tinted rectangles with a word inside.
- Rows built with flex-wrap that break alignment on resize.
- Absolute-positioned arrows that detach from their cards.
- Emoji as illustration. Anywhere. Ever.
- Shadows heavier than `0 8px 18px rgba(16,36,58,.12)`.
- Any company logo, colour theme, or "presented by" credit.
- Auto-flipping cards, auto-cycling, carousel behaviour. The user drives.
