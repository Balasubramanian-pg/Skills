# MASTER PROMPT — Icon-Driven Process Straw Model (HTML)

You are producing a single self-contained HTML file: a **visual straw model**
of a business process, styled as an internal consulting training slide.

The diagram must SHOW, not TELL. A newcomer should be able to narrate the
process from the shapes and motion alone, before reading a single label.
No company branding, no logos, no emoji, no clipart, no paragraphs on the
front of any card.

## 3. LAYOUT PATTERNS

Choose based on FLOW SHAPE. All layouts use CSS grid, not flex-wrap.
Connectors are grid cells, not absolutely positioned.

- **Fan-out-then-merge** — context band on top → arrow splits → N source
  cards in a row → merge SVG → harmonising wide card → drop arrow →
  terminal wide card.
- **Linear chain** — single row of cards, wrap on return flow if the
  process loops.
- **Branch-and-rejoin** — one source card → fork → parallel stage cards →
  fork back → convergence card.

**Vertical rhythm matters.** Reduce the gap between fan-out sources and
merge point (~24px) and increase the gap between merge and the next stage
(~56px). This makes the merge read as a *result*, not a peer.

**Connectors** — three types, all managed by the packet system in §5:
| Type | Color | Speed |
|---|---|---|
| Split arrow | source hue | fast (8% of cycle) |
| Source-to-merge | source hue | slow (25% of cycle) |
| Merge trunk | amber | snap (4% of cycle) |
| Return / payment | green | reverse direction, slow |

## 5. ICON QUALITY BAR — read twice

This is where most attempts fail. A cheap icon is worse than no icon.

**Every icon must:**
- Be inline `<svg viewBox="0 0 200 72">`, stroke-based, 1.4–1.8px strokes,
  round caps and joins, grid-aligned.
- Depict an **action or transformation**, not a noun. If the step is
  "Coding Department," the icon is *free text becoming code chips*, not a
  folder. If the step is "Clearinghouse," the icon is *claim → gate →
  pass/reject branches*, not a funnel.
- Contain **at least 3 distinct visual elements** telling a mini-story:
  input, mechanism, outcome.
- Use the card's own accent as primary, neutral ink for structure, and
  green/red only for semantically good/bad outcomes.
- Read clearly at 100% zoom. If it looks like a placeholder, redraw.

**Never:**
- Emoji, unicode glyphs, icon fonts, SVG clip-art bundles.
- A single rectangle labelled with a concept. That is a box, not an icon.
- Generic magnifying glasses, gears, funnels — unless paired with what goes
  in and what comes out.
- Inconsistent stroke weights across cards.
- Stray marks that don't participate in the metaphor.

**Self-audit before returning:** for each icon, silently answer — *"Would a
designer call this intentional, or cheap?"* If cheap, redraw. If two icons
in the set feel like different hands drew them, unify the stroke weight and
corner radii.

**Worked examples of the bar:**
| Weak | Strong |
|---|---|
| Folder (for "Coding") | Free-text note → arrow → 3 code chips |
| Funnel (for "Filter") | Claim → gate with ticks → two branches (pass/reject tokens) |
| Gear (for "ETL") | Three distinct shapes (circle/square/triangle) → crusher → green grid table |
| Document (for "Claim") | Barcode + 837 code tag + validation badge |
| Cylinder (for "Database") | Rows streaming → cylinder + green live dot |

## 6. MOTION SYSTEM — causal packets, not dashes

**Never use marching dashes.** Marching dashes are locomotion without
direction and the brain tunes them out in ~400ms. Use **packets**: single
bright dots with glow and a short trail travelling along a static dim base.

### The four laws

1. **Packets, not dashes.** Static breathing base line at `stroke-width:1.2`,
   `opacity` 0.4↔0.7 over 4s. On top: a `stroke-width:2.4` dashed segment
   with `stroke-dasharray:3 200` travelling via `stroke-dashoffset`.
2. **Glow halo.** Every packet has
   `filter:drop-shadow(0 0 3px <accent>) drop-shadow(0 0 6px <accent>40%)`.
   A single dot reads as a bead; a halo reads as a comet.
3. **Stagger, then causality.** Sources fire 0.25–0.35s apart. The merge
   trunk fires only *after* all sources have arrived. The trunk is a
   **response**, not an echo.
4. **Three timescales.** Ambient (base breathing, ~4s), rhythmic (packets
   in a 4s loop), reactive (hover/flip at 0.15s). If everything moves at
   the same speed, nothing moves.

### Reference timings (4-second cycle)

```
0.00s  split-1 launches          (fast: 8% of cycle)
0.15s  split-2 launches
0.30s  split-3 launches
0.90s  source-A packet launches  (slow: 25% of cycle)
1.20s  source-B packet launches
1.50s  source-C packet launches
1.90s  source-A arrives → junction pulse
2.20s  source-B arrives → junction pulse
2.50s  source-C arrives → junction pulse + ripple
2.70s  trunk packet launches     (snap: 4% of cycle)
2.86s  trunk arrives → sink glow begins
3.00s  drop arrow launches
```

### Arrowhead flash

Heads flash on packet arrival: `opacity .5 → .85 → .5`, `filter:drop-shadow`
peak at 6px. Peak at `.85`, not `1.0` — respects WCAG 2.3.1 while looking
identical.

### Junction ripple

On merge arrival, expanding ring `r:8→28`, `opacity:.7→0` over 0.5s.
The handshake should *detonate*, not just pulse.

### Hover-pause

`:has(.card:hover)` freezes every packet and head mid-stride so the user
can inspect a card while the movie holds. Release to resume.

### Reduced motion

`@media (prefers-reduced-motion:reduce)` disables every animation and
collapses flip duration to 0.01ms. Static diagram must be fully legible.

## 7. POLISH LAYER — the 10% that makes it feel premium

Every item below is required unless input says otherwise.

**Layered shadows** (never single-shadow):
```css
/* rest */
box-shadow:
  0 1px 1px rgba(16,36,58,.04),
  0 2px 4px rgba(16,36,58,.04),
  0 6px 12px rgba(16,36,58,.03);
/* hover */
box-shadow:
  0 1px 2px rgba(16,36,58,.05),
  0 4px 8px rgba(16,36,58,.06),
  0 14px 30px rgba(16,36,58,.07);
```

**Specular highlight** — cursor-following radial gradient on the front face:
```css
.face.front::after{
  content:"";position:absolute;inset:0;border-radius:2px;
  background:radial-gradient(circle 260px at var(--mx,50%) var(--my,50%),
    rgba(255,255,255,.55) 0%, transparent 55%);
  opacity:0;transition:opacity .35s;pointer-events:none;
  mix-blend-mode:overlay;
}
.card:hover .face.front::after{opacity:1}
```
Dark cards use `rgba(159,211,214,.42)` instead of white.

**Magnetic tilt** — max 2.4° on either axis, applied to `.face.front` only
(never the flip container):
```js
const dx = (e.clientX-rect.left)/rect.width - .5;
const dy = (e.clientY-rect.top)/rect.height - .5;
front.style.setProperty('--rx', (-dy*2.4)+'deg');
front.style.setProperty('--ry', ( dx*2.4)+'deg');
front.style.setProperty('--mx', (e.clientX-rect.left)+'px');
front.style.setProperty('--my', (e.clientY-rect.top)+'px');
```
Reset both to `0deg` on mouseleave and on flip.

**Grain overlay** — `.slide::before` with SVG `feTurbulence` at
`opacity:.025`, `mix-blend-mode:multiply`, `pointer-events:none`.
This is the "printed on fine stock" trick. Costs nothing perceptually —
until removed, and everything feels suddenly digital.

**Vignette** — `.slide` background:
`radial-gradient(120% 80% at 50% 0%, #fff 0%, #fafbfc 100%)`.

**Hover isolation** — hovering the grid dims all cards to `.45` opacity;
hovered/focused/flipped card returns to `1` and lifts `translateY(-2px)`.

## 8. FLIP INTERACTION

- Click / tap any card → `rotateY(180deg)` in 0.62s
  `cubic-bezier(.4,.15,.2,1)`.
- Keyboard: `Enter` and `Space` toggle. Cards are `tabindex="0"`,
  `role="button"`, and toggle `aria-pressed`.
- `:focus-visible` shows a 2px accent outline stacked with the resting shadow.
- Reset tilt (`--rx`, `--ry` → `0deg`) when a card flips, so the invisible
  front face doesn't carry a stale transform.
- Multiple cards may be flipped simultaneously.

## 9. CONTENT RULES

- Chips: 2–4 per card, uppercase, standard industry codes or 1–2 word tags.
- Theory back: **2–3 sentences**, plain language. Explain *why* this step
  exists and *what breaks* if it fails. No bullet lists, no headers, no
  marketing voice.
- Step numbers appear on both faces (ghost on front, kicker on back) so
  sequence stays legible when several cards are flipped.
- Terminal sink band: name + acronym, one-line purpose, then source pills.
- Legend under the grid: one line per color stream, 22px color swatch + label.

## 10. ALIGNMENT MATH — the craft detail

When a merge SVG's `viewBox` doesn't match the grid cell's rendered width,
`preserveAspectRatio="none"` stretches the SVG and the paths drift away from
card centers. **Do the math:**

1. Measure the grid cell width (e.g. 1104px).
2. Compute each card's center in grid coordinates:
   `centerX = (n - 0.5) * (cellWidth + gap) + offset`
   For 3 equal columns of 340px with 42px gaps in a 1104px grid:
   `centerX = 170, 552, 934`
3. Set `viewBox="0 0 <gridWidth> <height>"` exactly.
4. Re-derive every path coordinate from those exact centers.

Once corrected, everything feels 20% more "drawn" even though nothing
visibly moved. The eye catches drift on third viewing.

## 11. ANTI-PATTERNS — do not ship any of these

- Wall-of-text cards, paragraphs on the front face.
- Icons that are just tinted rectangles with a word inside.
- Rows built with flex-wrap that break alignment on resize.
- Absolutely-positioned arrows that detach from their cards.
- Emoji as illustration. Anywhere. Ever.
- Single-shadow cards (looks like a default Bootstrap card).
- Marching-dash connectors (locomotion without direction).
- Ghost numbers missing or at weight below 800 (loses the editorial feel).
- Shadows heavier than `0 20px 40px rgba(16,36,58,.08)`.
- Company logos, color themes, "presented by" credits.
- Auto-flipping, auto-cycling, carousel behavior. The user drives.
- Card heights that shift on flip.

## 13. WHEN IN DOUBT

- Prefer **less ink, more negative space**.
- Prefer **one moving element per path** over many.
- Prefer **one extra beat of animation** over one extra paragraph of text.
- If a card's front can't be understood without reading the chips, the icon
  failed. Redraw the icon.
- If the diagram feels busy, remove a color before removing a step.

The finished artifact should feel like it was **hand-set by a designer who
cared about the last 5%** — not generated by a template. That is the bar.
